# Authoritative result tables (data-governance record)

*Added 2026-11-12 under docs/148 P0-2 / P0-3. This file travels inside the
submission deposit under `Table_Source_Data/` so an external reader can tell,
without ambiguity, which CSV corresponds to the manuscript.*

## Why this record exists

The repository accumulated three mutually inconsistent `mr_results*.csv`
files. Shipping them together let a reader reproduce Table 2 or a stale
pre-correction number depending on which file they opened — a reproducibility
and data-governance failure, not a rounding issue. Only one table is
authoritative; the others are retained on disk for audit but are **excluded
from the deposited deliverable**.

## The one authoritative MR result table

| Role | File | Table 2 value (BMD total → fracture, IVW β) | SHA256 (first 12) |
|---|---|---|---|
| **AUTHORITATIVE** | `mr_results_corrected.csv` | −0.3371 | `ebc49253cfd0` |
| EXCLUDED — raw placeholder-N scale | `mr_results.csv` | −1.1943 (×3.543 too large) | `e1feacb78bed` |
| EXCLUDED — superseded pre-G6 backup | `_backup_pre_G6/mr_results_corrected.csv` | −0.3371 (but OA rows differ 2–5×) | `699e8edec63f` |

The authoritative table is the truth source for manuscript Table 2 and is read
by the downstream scripts `code/173`, `code/172`, `code/177`, `code/181`,
`code/171c`, `code/178` and `code/14_figure3_mr_forest.py`. Its matched
MR-PRESSO companion is `mr_presso_results_corrected.csv` (SHA256 prefix
recorded in the package MANIFEST).

**Scale chain** (verified independently by `code/343_scale_chain_verify.py`):
the deposited GWAS summary statistics carry a placeholder exposure N=400,000;
restoring the verified BMD N=31,873 multiplies each BMD β and SE by
√(400,000/31,873)=3.5426 (per-SNP z unchanged). For the binary knee-OA outcome
the linear-probability reconstruction is converted to log-odds by
1/√[K(1−K)]=3.389 (K=0.0964, estimated not assumed). `mr_results.csv` is the
pre-reconstruction raw output and must not be used to quote any manuscript value.

## Per-SNP instrument tables (STROBE-MR; P0-3)

Table 2's IVW, MR-Egger intercept, Cochran Q, I², weighted median and
leave-one-out columns are derived from the per-SNP harmonised instrument
tables in `Table_Source_Data/harmonised/`. These are delivered (12 files,
≈95 KB) so that a reviewer can re-derive the reported statistics without the
project's own pipeline:

```
python3 code/334_data_level_trust_but_verify.py     # 18/18 independent checks
python3 code/343_scale_chain_verify.py              # scale chain + SHA256 list
```

Re-derivation uses an independent IVW implementation (numpy), not the
`code/13` MR pipeline. Harmonised BMD_total→fracture SHA256 prefix
`c502fcb26416`; BMD_total→OA_knee `8ead501fbaee` (full list in the MANIFEST
and printed by `code/343`).

## What is intentionally NOT in the deposit

- `mr_results.csv` — raw placeholder-N scale; retained on disk for the audit
  trail only (see docs/146, docs/148, docs/123).
- `_backup_pre_G6/` — the full pre-G6 directory (older harmonised tables and
  result files). Retained on disk; superseded in every OA-related row.
- Bulk PLINK clumping inputs, raw GWAS extracts — deterministically
  regenerated by the deposited scripts from the source summary statistics.

None of these exclusions removes information needed to reproduce a reported
result: every reported number is recoverable from the authoritative table and
the delivered harmonised tables.
